# Technical Architecture Decisions (High-Level)

> **Owns:** top-level technical choices and the decision register. **Not here:**
> data model → `05`; testing → `02`/`06`; group domain rules →
> `docs/specs/tech/groups-contract.md`. **Load when:** always (always-load).

## System map

`Expo React Native UI`
-> `Session domain + autosave orchestration`
-> `Local repository layer (Drizzle + SQLite)`
-> `Auth-gated sync v2 cycle (pull→push→pull; per-row dirty bit + LWW) + first-sign-in bootstrap`
-> `Supabase backend (local-first dev/test via Supabase local stack)`

## Decision register

Every row is adopted unless it says otherwise. **Source** is the owning path;
follow a linked spec when your task touches that decision's area.

| Decision | Why | Source |
| --- | --- | --- |
| `Expo + React Native + TypeScript` with `Expo Router` file-based routing on the UI side, and on-device `SQLite` + Drizzle ORM underneath | One codebase for a phone-first app, a structure predictable for humans and agents, and offline-first storage with a typed schema and migrations. | `apps/mobile/package.json`, `apps/mobile/app/`, `apps/mobile/src/data/schema/`, `apps/mobile/drizzle/` |
| iOS takes the UIKit scene lifecycle natively from Expo SDK 58; no `expo-build-properties` opt-in | iOS 27 requires it, and SDK 58 owns the scene delegate and single-window manifest by default. | `apps/mobile/app.config.ts` |
| Root route access (sign-in / first-sync block / app) is enforced by the navigator: one `Stack.Protected` group per level, never unmounting the root navigator to gate | Unmounting the root navigator reverts the route, so a guard that swapped it for a `<Redirect>` or a block looped on sign-in and sign-out; `Stack.Protected` drops the old level's routes and lands on the first one still declared. | `apps/mobile/components/navigation/root-stack.tsx`, `apps/mobile/src/navigation/root-route-access.ts`, `docs/specs/ui/navigation-contract.md` |
| Continuous local autosave is a domain/data-layer contract, with RN lifecycle events mapped to flush triggers through adapter contracts; timing constants live in the implementing code and its tests | Persistence is verifiable without a screen, and per-feature tuning does not move the architecture. | `apps/mobile/src/session-recorder/draft-autosave.ts` |
| Session completion persists `completedAt` and a materialized `durationSec`, and logged session exercises persist a canonical `exercise_definition_id` beside display name/origin metadata | Keeps completion reads and sorts deterministic without recomputing duration, and prevents name-only drift so history, grouping and per-exercise lookups have a stable identity. | `apps/mobile/src/data/schema/sessions.ts`, `apps/mobile/src/data/schema/session-exercises.ts` |
| Exercise and mapping metadata are retroactive: current metadata reinterprets all history and analytics | The product expects edits to apply globally, and no analytics materialization exists to rewrite. | `docs/specs/00-product.md` |
| Load distribution is stored as `total_load` or `per_side_load`; muscle analytics normalizes to per-side volume before applying the mapping role factor (`primary = 1`, `secondary = 0.5`) | Makes load meaning explicit without equipment-name inference or per-set duplication. | `apps/mobile/src/data/schema/exercise-definitions.ts`, `apps/mobile/src/data/muscle-analytics.ts` |
| Ordinary and bodyweight-aware load resolve once in a pure TS boundary under an explicit policy (`ordinary`, `personal` or `group`) | One arithmetic kernel serves mobile, groups and coaching, and a typed policy stops the personal missing-reading zero fallback leaking into strict group scoring. | `docs/specs/tech/bodyweight-load-contract.md` |
| Session muscle load, exercise PRs and completed-session volume comparisons are pure derived projections — no achievement, comparison or sync persistence | `session-insights` centralizes the arithmetic and applies current metadata; `deriveSessionPersonalRecords` stays the pure replay reference that Jest holds the facts-backed PR list to. | `apps/mobile/src/session-insights/`, `apps/mobile/src/exercise-calculations/best-set.ts` |
| History metrics derive once into device-only `exercise_session_facts`: one row per completed session × linked exercise definition holding that session's best 1RM, top weight, volume, working sets and a PR flag per metric. SQLite triggers queue stale definitions, every read drains the queue, and a rules-version marker forces one full rebuild per device after a rule change. The table is never synced | Answering "is this a PR?" by replay costs O(all sets ever logged); per-session bests make it an indexed read. Triggers catch every write path (pull-apply and imports included) without call-site discipline, deriving from synced raw rows needs no wire change, and a full rebuild is the Jest oracle. | `apps/mobile/src/data/exercise-session-facts.ts`, `apps/mobile/drizzle/0012_exercise_session_facts_triggers.sql`, `docs/specs/05-data-model.md` "Exercise session facts" |
| Completed-session sharing captures the rendered summary card to a temporary PNG, then invokes the native share sheet | The preview is the artifact, so there is no upload, share ledger or durable media record; it omits private gym/location data. | `apps/mobile/components/session-complete/session-share-sheet.tsx`, `apps/mobile/src/session-insights/sharing.ts` |
| Browsing and Progress preferences are account-scoped scalar/JSON keys in `expo-sqlite/kv-store` with typed defaults and synchronous durable saves. Independent device-local Working-set and Volume effort choices govern personal counts/strength records and volume totals/records; groups and coaching use the fixed rule of [[set.eligibility]] | Device keys keep the choices out of the data model and sync scope. Sign-out clears active values but preserves stored choices, and a database wipe does not touch the key-value store. Adapters pass the account's policy explicitly to the kernel, and the facts table stores its policy key so a changed choice rebuilds before the next read. | `apps/mobile/src/preferences/`, `docs/specs/05-data-model.md` "Device-local preferences" |
| Mobile auth bootstrap uses `Supabase Auth` client-safe credentials plus persisted session restore, exposed through one shared auth service/provider rather than route-local listeners; profiles live in `app_public.user_profiles` keyed `1:1` to `auth.users(id)`, provisioned lazily on first load/save. Missing auth config keeps local-only tracker routes available | An unconfigured build cannot produce a session, so the route layer stands aside while the sign-in screen still states that sign-in is unavailable. `username` stays app-owned while email/password stay in `Supabase Auth`, and auth/profile failures stay confined to the profile route. | `apps/mobile/src/auth/`, `supabase/migrations/20260304153000_m11_user_profiles.sql` |
| The Sync v2 wire contract is the `sync_push` / `sync_pull` RPC pair: push sends FK-ordered batches of typed per-row envelopes under per-row last-write-wins on a client clock, and pull is an idempotent per-layer cursor drain | Typed server columns mean SQL and analytics work day one with no projection layer, and the client stays a per-row dirty bit — no event log or outbox — with deterministic, retry-safe convergence. | `docs/specs/tech/sync-v2-server-contract.md`, `apps/mobile/src/sync/cycle.ts` |
| Sync v2 server tables are user-scoped from day one: composite primary key `(owner_user_id, id)` with RLS `owner_user_id = auth.uid()`, and no shared or global catalog on the backend | Each user owns their own `id` keyspace, so two users may legitimately hold the same `id` (e.g. seeded `exercise_definitions.id`); ownership plus LWW means no cross-owner rejection path exists by construction. | `supabase/migrations/`, `docs/specs/tech/sync-v2-server-contract.md` |
| Mobile sync is auth-gated and non-blocking after app entry: a periodic foreground cycle runs PULL→PUSH→PULL until both ends are quiet for one round, scheduled by a four-state machine (offline / long-backstop / short-debounce / running) owning a single timer | Offline use survives on a restored session, stale configured auth routes to sign-in, missing auth config stays local-only, and the state machine guarantees at most one in-flight cycle. | `apps/mobile/src/sync/cycle.ts`, `apps/mobile/src/sync/scheduler.ts`, `docs/specs/10-api-authn-authz-guidelines.md` |
| Sync success reflects real convergence, not a clean return: `runSyncCycle` returns a classified outcome (`converged` / `auth-required` / `fk-violation` / `internal`) and the scheduler advances `lastSuccessAtMs` only on `converged`. A pulled row violating local FK enforcement is classified before cursor advance, keeping page-rollback / cursor-not-advanced semantics; push-side FK closure is preflighted from a declared syncable FK graph, and local orphans persist to `sync_quarantine` out of push selection | A non-converged cycle must record no false success and stay visible until a later converged cycle clears it, and valid rows beside an orphan keep pushing so one bad row cannot wedge the backlog. | `apps/mobile/src/sync/cycle.ts`, `apps/mobile/src/sync/fk-graph.ts`, `apps/mobile/src/sync/quarantine.ts` |
| First-sign-in bootstrap seeds the starter exercise catalog only when the first full pull returns zero server rows, then lets the normal cycle push the seeded (dirty) rows | Gated on `bootstrap_completed_at` it runs once per device per account, and seeding only an empty remote prevents duplicate catalogs while a fresh user still gets the starter exercises. | `apps/mobile/src/sync/bootstrapper.ts`, `apps/mobile/src/data/exercise-catalog-seeds.ts` |
| Supabase OAuth agent tokens are denied direct domain-table and sync-RPC access by a restrictive `client_id IS NULL` RLS policy; read-only coaching access flows through a dedicated BoGa3 API | OAuth tokens otherwise inherit ordinary authenticated-table privileges; the restrictive policy makes the agent API their only training-data boundary. | `supabase/migrations/20260725175643_m21_agent_access_boundary.sql`, `supabase/functions/agent-api/`, `services/boga-mcp/` |
| Private gym coordinates sync as nullable owner-scoped columns on user-owned `gyms`, and GPS access is foreground-only behind an injectable location service and a pure matcher that both gym UI reads take as a parameter (the sheet's nearby suggestion never preselects) | GPS gyms need backup/restore parity without public places, check-ins or shared location records; injection keeps native permission behavior out of the screens, prevents background location use, and makes radius/accuracy/tie behavior unit-testable. | `apps/mobile/src/data/schema/gyms.ts`, `apps/mobile/src/location/` |
| Minimal app diagnostics use Supabase `public.app_logs` plus a mobile logging helper; client access is insert-only and logging is non-blocking | Captures production auth/sync failure breadcrumbs without an observability vendor or a user-facing dashboard. | `supabase/migrations/20260507120000_create_app_logs.sql`, `apps/mobile/src/logging/logEvent.ts` |
| Every theme is light; dark mode is not a product goal, and `app.config.ts` pins `userInterfaceStyle: "light"` | `uiRoles` has no dark variants, and `"automatic"` gives OS-owned chrome (`Alert.alert`, keyboard, native pickers) a dark appearance over light app content. | `apps/mobile/app.config.ts`, `apps/mobile/components/ui/tokens.ts`, `docs/specs/ui/ux-rules.md` "Appearance" |
| Colour roles are generated in CIE LCh from four seeds (`ground`, `accent`, `record`, `viz`): each role keeps a fixed L\* and takes its seed's hue and scaled chroma. The user picks one of four presets (Warm, Slate, Forest, Plum) or a hue on a ring, stored per device in `expo-sqlite/kv-store`, read synchronously when `tokens.ts` first evaluates and applied at the next launch; an unreadable choice opens in Warm and is logged | Contrast floors hold for any seed because contrast follows lightness, which seeds never set — LCh not OKLCH because the roles are gated in L\*. Per device keeps the choice out of sync scope; next launch rather than live because module-scope `StyleSheet.create` must keep working and a release build cannot restart itself. | `apps/mobile/components/ui/theme.ts`, `apps/mobile/components/ui/theme-launch.ts`, `docs/specs/ui/design-language.md` |
| The design-language typefaces are embedded in the binary by the `expo-font` config plugin, never loaded at runtime; screens name a face as `{ fontFamily, fontWeight }` from `uiFonts` | Embedding registers the faces before JS runs, so there is no async load, splash gate or system-font flash reflowing numeric columns, and one name resolves on both platforms without a PostScript map. Web falls back to system fonts. | `apps/mobile/app.config.ts`, `apps/mobile/components/ui/tokens.ts`, `docs/specs/ui/design-language.md` |
| The icon set is vendored Lucide path data rendered by one `Icon` primitive over `react-native-svg`, not the `lucide-react-native` package; Unicode characters are not icons | About 25 icons are needed; the package ships ~1,600 (27.8 MB) and Metro does not tree-shake a barrel import, so one careless import bundles them all. | `apps/mobile/components/ui/icon.tsx`, `apps/mobile/components/ui/icon-glyphs.ts`, `apps/mobile/components/ui/LICENSE.lucide` |
| Design-token conformance is enforced by an executable budget ratchet: each rule fails both over AND under its budget, and a zero-tolerance `legacyVocabulary` rule rejects any retired `uiColors` / `uiRadius` / `UiText` name in `app`, `components` or `src` | Only the dimension a script checked reached full adoption, and failing under budget means the count can only fall. | `apps/mobile/scripts/check-ui-guardrails.js`, `apps/mobile/scripts/ui-guardrails.config.js`, `scripts/lanes.tsv` |
| The group record is a server-side share ledger (`group_session_shares`) written by a failure-isolated trigger on `app_public.sessions`; group reads are `SECURITY DEFINER` RPCs that read content through from members' Sync v2 rows (the viewing device counts card sets) into a disposable local cache | Edits, deletes and in-progress updates flow through with no copy or diff; it needs no client sync change or second push path, authorization stays in the database, and a group failure cannot break personal sync. | `supabase/migrations/20260911120000_m22_group_record.sql`, `apps/mobile/src/groups/`, `docs/specs/tech/groups-contract.md` |
| The group stream is one persistent table, `group_events`: each item is a row written once when it happens by a failure-isolated session or membership trigger, never deleted by the app. Session cards still read content, position and visibility live from the member's rows | One producer instead of read-time assembly from several sources; later item kinds append to the same table. | `supabase/migrations/20260913153000_m25_group_events.sql`, `docs/specs/tech/groups-contract.md` |
| The group evaluator is the `group-eval` Supabase Edge Function: failure-isolated triggers on the member's Sync v2 rows enqueue work, a `pg_net` kick plus a `pg_cron` backstop invoke it under a Vault-held shared secret, and it normalizes shared sets with the app's own TS set rules; ranking and events stay SQL | One implementation of the set rules runs on devices and on the server, so no SQL mirror can drift. The queue, generation guard and backoff make every change durable, and nothing on this path can abort `sync_push`. | `supabase/functions/group-eval/`, `apps/mobile/src/groups/set-facts.ts`, `docs/specs/tech/groups-contract.md` |
| Group leaderboards are materialized per member in `group_board_entries`: each evaluator apply recomputes one (group, group exercise) target from the set facts and derives the stream events and board history from the diff against stored entries. A certification pins the raw synced values of the set it attests and is voided when that fingerprint changes or the set leaves; active-session records are provisional, so voids are emitted only for completed sessions | Recompute-and-diff never patches entries incrementally, so edits, deletes, links, load-mode changes, rules bumps and certification changes cannot drift apart; entries read as indexed SQL, and the fingerprint pin needs no TS set rule in SQL. | `supabase/migrations/20260914120000_m25_group_boards.sql`, `docs/specs/tech/groups-contract.md` |
| A member's exercise → group-exercise links are the tenth Sync v2 entity, `exercise_group_links`, with deterministic id `<group_id>:<exercise_definition_id>`; its only FK is to the synced `exercise_definitions` parent, and `group_id` / `group_exercise_id` are plain text with no FK | Links are the member's own data, so they back up, sync and work offline like the rest; the deterministic id gives one group exercise per personal exercise per group with no server constraint (unlink is a tombstone, relink undeletes the same id under LWW), and FK-free columns keep Sync v2 independent of group tables. | `apps/mobile/src/data/exercise-group-links.ts`, `supabase/migrations/20260913170000_m25_exercise_group_links.sql` |
| Session planning is a separate synced domain: four plan entities and three performed-domain provenance links expand Sync v2 to sixteen entities over five layers, gated on protocol 4 | Plans are authored intent, materialized into ordinary performed rows. | `docs/specs/tech/session-planning-contract.md` |
| Group competition representation is versioned separately from private sync: Volume/1RM use explicit ordinary or normalized units with allowlisted public projections and group-scoped disposable caches, while source kg and the immutable witness audit stay private server facts | Protocol 4 is the only group representation; the pre-V4 server and activation step are removed. | `docs/specs/tech/group-competition-contract.md` |
| MVP backend platform is `Supabase (Postgres + Auth + RLS)`, and backend work must support a local backend runtime with high-fidelity local verification before deployment; `Cloudflare Workers + D1` stays a documented lean contingency only | Better local-test fidelity and SQL portability than the edge fallback, which would widen auth/authz scope; local verification minimizes post-deployment debugging. | `docs/specs/02-quality-and-test-gates.md` |
| Local parallel-agent development uses git worktrees with slot-derived runtime isolation, an explicit slot lease that every runtime command requires, agent-owned teardown on PR merge, and no nested worktrees | Agents on one machine need isolated stacks, ports, data and installs, and nesting contaminates the parent. Automatic cleanup heuristics misfired on squash merges and fresh worktrees, leaking merged stacks and destroying live ones. | `docs/specs/12-worktree-config-and-isolation.md`, `scripts/worktree-start.sh`, `scripts/worktree-release.sh` |
