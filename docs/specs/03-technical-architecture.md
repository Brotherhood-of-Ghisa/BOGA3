# Technical Architecture Decisions (High-Level)

> **Owns:** top-level technical choices and the decision register. **Not here:** data model → `05`; testing → `02`/`06`. **Load when:** always (always-load).

## Purpose

Capture top-level architecture decisions for MVP, with clear `Adopted` vs `Planned` status.

## System map

`Expo React Native UI`
-> `Session domain + autosave orchestration`
-> `Local repository layer (Drizzle + SQLite)`
-> `Auth-gated sync v2 cycle (pull→push→pull; per-row dirty bit + LWW) + first-sign-in bootstrap`
-> `Supabase backend (M5 selected; local-first dev/test via Supabase local stack)`

| First-sign-in bootstrap seeds the starter exercise catalog only when the first full pull returns zero server rows, then lets the normal cycle push the seeded (dirty) rows | `Adopted` | Runs once per device per account (gated on `bootstrap_completed_at`); seeding only an empty remote prevents duplicate catalogs while guaranteeing a fresh user keeps the starter exercises. | `apps/mobile/src/sync/bootstrapper.ts`, `apps/mobile/src/data/exercise-catalog-seeds.ts` |

| Minimal app diagnostics use Supabase `public.app_logs` plus a mobile logging helper | `Adopted` | Captures production auth/sync failure breadcrumbs without adding an external observability vendor or user-facing dashboard; client access is insert-only and logging is non-blocking. | `supabase/migrations/20260507120000_create_app_logs.sql`, `apps/mobile/src/logging/logEvent.ts` |
| Pull-side local SQLite FK failures are classified before cursor advance | `Adopted` | A pulled child row that violates local FK enforcement is reported as `LOCAL_FK_VIOLATION`, emits a sanitized `sync.pull_local_fk_violation` diagnostic, preserves page rollback / cursor-not-advanced semantics, and returns the structural `fk-violation` cycle outcome. | `apps/mobile/src/sync/cycle.ts`, `apps/mobile/app/__tests__/sync-cycle-convergence.test.ts` |

| Scheduler sync success reflects real convergence, not a clean return | `Adopted` | `runSyncCycle` returns a classified `SyncCycleOutcome` (`converged` / `auth-required` / `fk-violation` / `internal`), and the scheduler advances `lastSuccessAtMs` only on `converged`; all non-converged outcomes record no false success and stay visible until a later converged cycle clears them. | `apps/mobile/src/sync/cycle.ts`, `apps/mobile/src/sync/scheduler.ts`, `apps/mobile/app/__tests__/scheduler-status-accessor.test.ts` |
| A member's exercise → group-exercise links are the tenth Sync v2 entity, `exercise_group_links`, with deterministic id `<group_id>:<exercise_definition_id>`; its only FK is to the synced `exercise_definitions` parent (`on delete no action`), and `group_id` / `group_exercise_id` are plain text with no FK | `Adopted` (M25) | Links are the member's own data, so they back up, sync, and work offline like the rest of it. | Local parallel-agent development uses git worktrees with slot-derived runtime isolation, an explicit slot lease (`boga worktree start`) that every runtime command requires, agent-owned teardown on PR merge (`boga worktree release`, GitHub PR state as the only completion signal), and a harness-independent no-nested-worktree rule | `Adopted` | Multiple agents on one machine need isolated Supabase containers/ports/data, Metro ports, simulator targets, dependency installs, and generated config; refusing nested worktrees prevents parent `node_modules`, TypeScript, and watcher contamination. | The group record is a server-side share ledger (`group_session_shares`), written by a failure-isolated trigger on `app_public.sessions` from session start time vs. membership periods. Group reads are `SECURITY DEFINER` RPCs that read content through from members' Sync v2 rows (raw live set rows; the viewing device computes card metrics with the recorder's TS), and devices pull into a disposable local cache. | `Adopted` (M22) | In-progress updates, edits, and deletes flow through with no copy or diff. It needs no client sync change or second push path, and group failures cannot break personal sync. Authorization stays in the database. | `supabase/migrations/20260910120000_m22_groups_membership.sql`, `supabase/migrations/20260911120000_m22_group_record.sql`, `apps/mobile/src/groups/`, `apps/mobile/src/data/schema/group-cache.ts`, `docs/specs/tech/groups-contract.md` |
| The group stream is one persistent table, `group_events`: each item is a row written once when it happens and never deleted by the app. A failure-isolated session trigger writes `session` items from the share ledger; a membership trigger writes `joined` / `left` / `removed` atomically with the period change. `group_stream` reads only this table, while session cards still read content, position, and visibility live from the member's rows. | `Adopted` (M25) | One way of producing the stream instead of read-time assembly from two sources plus a later record table. Later item kinds (records, voids, links) are appended to the same table with no read-time merge. Live card content keeps in-progress updates, edits, and deletes flowing through. The wire contract is unchanged. | `supabase/migrations/20260913153000_m25_group_events.sql`, `docs/specs/tech/groups-contract.md` §2.6 |
| The group evaluator is the `group-eval` Supabase Edge Function. Failure-isolated triggers on the member's Sync v2 rows enqueue work into `group_eval_queue`; a `pg_net` kick (at most one per transaction) and a `pg_cron` sweep (every 30 s) invoke it, authenticated by a Vault-held shared secret. It normalizes shared sets into `group_set_facts` with the app's own TS set rules, loaded by relative path (`apps/mobile/src/groups/set-facts.ts`, no `@/` imports, `.ts` specifiers under the mobile tsconfig's `allowImportingTsExtensions`). Ranking and events stay SQL. | `Adopted` (M25) | One implementation of the set rules runs on devices and on the server, so there are no SQL mirrors to keep in parity. Records appear seconds after sync, which is accepted. The queue, generation guard, and backoff make every change durable, and nothing on this path can abort `sync_push`. The evaluator is not a client API, so the M22 rejection of an Edge Function group API (authorization in app code) does not apply. | `supabase/migrations/20260913180000_m25_group_eval.sql`, `supabase/functions/group-eval/`, `docs/specs/tech/groups-contract.md` §2.8–§2.10 |
